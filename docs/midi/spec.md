# nsf2mid 仕様書（morokoshi の MIDI 変換）

NSF / GBS / SPC を読み取り、テンポ検出付きで MIDI に変換する。morokoshi の Save → MIDI から使う。

> 2026-11-06（morokoshi v2.9.25）に別アプリ nsf2mid（v0.1.44）を morokoshi へ統合した。
> ソースは `src/nsf2mid_core/`、回帰テストは `tools/regress.py`。バージョンは morokoshi の `APP_VERSION` で管理する。
> nsf2mid の GUI・簡易再生は廃止（下の「Phase 4 GUI」は記録として残す）。CLI は回帰テスト・調査用に残す。

## 方針

- 既存の nsf2midi（zophar.net）の不満点を解消する
  - テンポ非対応 → フレーム単位の発音タイミングからテンポを検出し、クオンタイズ済み MIDI を出力
  - ノートオン判定が不自然（例: ドラクエ2 の発音中の duty 比変化が再ノートオン扱いになる）
    → duty 変化・音量エンベロープ・ビブラートは同一ノート内の変化として扱う
- 拡張音源は後回し（Phase 5）

## 構成（src/nsf2mid_core/）

| ファイル | 役割 |
|:---|:---|
| `nsf2mid.py` | CLI エントリ。MIDI 構築・各種出力。`convert(args)` が 1 曲分の変換（morokoshi から使用）。引数なしは使い方を表示 |
| `gbs.py` | GBS ヘッダ解析・メモリマップ・バンク切替・INIT/PLAY 呼び出し・レジスタ書き込み記録（NSFPlayer と同じインターフェース、v0.1.27） |
| `cpu_sm83.py` | ゲームボーイ CPU コア（SM83 / LR35902、v0.1.27） |
| `gb_apu.py` | ゲームボーイ APU 状態モデル（P1/P2/TRI/NOI のキーで返すので以降の処理は NSF と共通、v0.1.27） |
| `cpu6502.py` | 6502 CPU コア（2A03: 10進モードなし、主要な非公式命令対応） |
| `nsf.py` | NSF ヘッダ解析・メモリマップ・バンク切替・INIT/PLAY 呼び出し・レジスタ書き込み記録。`$4015` 読み出しはライブ APU モデルから返す |
| `apu_state.py` | APU 状態モデル（長さカウンタ・エンベロープ・スイープ・線形カウンタ・フレームシーケンサ・DMC 再生区間）。音声合成はしない |
| `notes.py` | ノート抽出（P1/P2/TRI）・リバーブ余韻判定・グライド統合・テンポ用オンセット |
| `tempo.py` | グリッド検出・拍子（2分割/3分割）判定・テンポマップ・フレーム→ティック変換 |
| `drums.py` | ドラム抽出（ノイズ・DPCM → GM パーカッションのノート番号（ch 4 / 5）、1〜3ch の下降音ドラム → 元の音程のまま別トラック（ch 1〜3）、複数レートで鳴らす DPCM サンプル → 音程付きの別トラック（ch 5））・ドラム割当の上書き |
| `loop.py` | ループ点・ループ長・曲終端の検出 |
| `midi.py` | SMF（format 1）書き出し |

## 使い方

```
python src/nsf2mid_core/nsf2mid.py FILE.nsf [-t TRACK] [-s SECONDS] [-o OUTDIR] [--info] [--dump]
                      [--keep-tail] [--no-quantize] [--unit FRAMES] [--rows-per-beat N] [--tempo auto|half|double]
                      [--loops N] [--no-loop] [--drop-drums N] [--drum-map MAP]
```

| オプション | 内容 |
|:---|:---|
| `-t` | 曲番号（1 始まり、既定はヘッダの開始曲） |
| `-s` | エミュレートする最大秒数（既定 600）。ループ確定・曲終了で自動停止 |
| `--dump` | Phase 1 のダンプ（writes/frames/tracker）も出力 |
| `--keep-tail` | リバーブ余韻もノート長に含める（既定は余韻の直前でノートオフ） |
| `--no-quantize` | グリッドへのスナップをしない（テンポには合わせる） |
| `--unit` | グリッド単位（フレーム数）を手動指定 |
| `--rows-per-beat` | 1 拍あたりの行数を手動指定（4 = 16分音符グリッド）。全区間が同じ行数になり、シャッフル・3 連ノリの自動検出も止まる（GUI には無い） |
| `--tempo` | 自動検出したテンポの補正（v0.1.19〜）: `auto`（既定）/ `half`（半分 = 行数を 2 倍）/ `double`（2 倍 = 行数を半分）。区間ごとに検出後の行数へ適用するので、区間分割・3 連・シャッフルの検出はそのまま。`double` で行数が奇数（3 など）の区間は検出のまま（ログに表示）。`--rows-per-beat` 指定時は無効 |
| `--loops` | ループ部を何回書き出すか（既定 1 = イントロ＋ループ 1 回）。0 = ループ検出をしない（`--no-loop` と同じ、v0.1.19〜） |
| `--no-loop` | ループ検出をしない（`-s` の秒数をそのまま変換）。`--loops 0` と同じ |
| `--tri-octave` | 三角波の MIDI 出力のオクターブ移動（既定 0 = APU の物理的な音高） |
| `--programs` | P1,P2,TRI の GM 音色番号（0 始まり）。例 `"80,80,38"`、`-` で音色指定なし（既定: 指定なし） |
| `--triplets` | 3 連ノリの優先: `auto`（自動検出、既定）/ `on`（常に 3 連として出力）/ `off`（常に 2 分割） |
| `--drop-drums` | 下降音ドラム（三角波キック・矩形波タム）の閾値。この半音数以上下がり続ける短い音を別トラック（ch は元のまま）に分ける（v0.1.21〜、既定 3、0 = 分けない） |
| `--no-drop-drums` | `--drop-drums 0` と同じ（旧名 `--no-tri-drums` も可） |
| `--drum-map` | ドラム割当の上書き。例 `"3:0=42,12:0=36,DMC:E000:129:15=38"`（ノイズは `周期番号:モード`、DPCM は `DMC:アドレス16進:長さ:レート`） |

出力（既定: NSF と同じフォルダの `nsf2mid_out/`）:

| ファイル | 内容 |
|:---|:---|
| `*.mid` | MIDI（Track0: テンポマップ・4/4・ループマーカー、Track1-3: Ch1 Pulse / Ch2 Pulse / Ch3 Wave（ch 1-3）、拡張音源のトラック（ch 6〜、v0.1.25〜。下記「Phase 5 拡張音源」）、ドラムトラック: Ch4 Noise drums（ch 4）/ Ch5 DPCM drums（ch 5）/ Ch5 DPCM $ADDR（複数レートで鳴らすサンプル、ch 5、音程付き）/ 下降音ドラム Ch1 Pulse drums / Ch2 Pulse drums / Ch3 Wave drums（ch 1 / 2 / 3、元の音程）（いずれもヒットがある場合のみ）。v0.1.23〜 MIDI ch は NES のチャンネル番号に揃える（v0.1.22 までは noise / DPCM ch 10、下降音ドラム ch 11〜13）） |

※ 音程トラックは既定で音色（プログラムチェンジ）を出力しない（v0.1.7〜）。v0.1.5〜0.1.6 は GM 80。楽譜ソフト（Sibelius）は音色番号から楽器を決め、
  楽器の種類順にトラックを並べ替える。また 38（Synth Bass）はベース＝1 オクターブ上に記譜する移調楽器として
  扱われ、三角波が 1 オクターブ高く表示されていた（v0.1.4 まで）。
※ トラック名は Ch1 Pulse / Ch2 Pulse / Ch3 Wave / Ch4 Noise drums / Ch5 DPCM drums / Ch1 Pulse drums / Ch2 Pulse drums / Ch3 Wave drums。
  Sibelius はトラック名からも楽器を判定し、「Triangle」を打楽器のトライアングルとして打楽器セクションへ移していた（v0.1.5 まで）。
  Sibelius はスコア順（打楽器 → 鍵盤・シンセ …）に並べるため、ドラムトラックは上に来る。
| `*_notes.csv` | 抽出ノート・ドラム一覧（開始/ゲート終了/終了フレーム・余韻長・音名/ドラム名・ピーク音量・開始要因/分類根拠・ティック・音量推移） |
| `*_writes.csv` | （`--dump`）全 APU レジスタ書き込み |
| `*_frames.csv` | （`--dump`）フレーム末尾時点の各チャンネル状態 |
| `*_tracker.txt` | （`--dump`）トラッカー風の目視確認用ビュー |

トラッカー表示の記号:
- `*` = 周期上位レジスタ（$4003/$4007/$400B/$400F）への書き込み（位相リセット・エンベロープ再始動）
- `d` = duty 比変化 / `p` = 上位レジスタ書き込みなしの周期変化 / `~` = 平均律から 20 セント超ずれ
- 実効音量 0 でも `*` があれば `v0` 付きで表示

- `.nsf` のほか、NSF が入った zip（zophar.net 形式 `Foo (EMU).zophar.zip`）を直接指定できる（CLI・GUI・簡易再生とも）

## Phase 2 ノート判定

### 調査結果（ドライバごとの癖）

| 曲 | 観察 | 判定への反映 |
|:---|:---|:---|
| ドラクエ2 | 発音中に duty が D1→D2→D1→D0 と変化。`$4003` は書かれない | duty 変化ではノートオンしない |
| ドラクエ2/3 | ゲートオフで音量が急落し、D0・音量 2 の余韻が次の音まで続く（同じ音程） | 余韻として判定しノートオフ |
| ドラクエ4 | ゲートオフで音量 E→7 に急落し、その後ゆっくり減衰 | 同上（急落） |
| マリオUSA | 音量が B→1 まで減衰し、音量 1 で次の音まで保持 | 同上（低い床で保持） |
| ドラクエ3 / 2 街 | 発音中に音量が上下（トレモロ B→8→B） | 音量上昇ではノートオンしない |
| オホーツクに消ゆ | 音量が B,B,4,4,A,A,5,5,9,9,6,6… と 2 フレームごとに上下する減衰トレモロ。連打に聞こえるが `$4003` 書き込みは 1 回 = 1 音 | 同上 |
| オホーツクに消ゆ | 発音前に `$4015` を書き換えて**読み戻す**ドライバ | `$4015` 読み出しを実装（未実装時は無音になっていた） |
| スーパーマリオ | `$4003` 書き込みと同フレームで音量 0、次フレームから発音 | 無音フレームのトリガーを保留し、同じ音程で鳴り始めたらトリガーフレームを開始とする |
| ロックマン2 | 各音の直前に周期 0 でトリガー（無音）。三角波でピッチ急降下のドラム | 周期範囲外は無音扱い。短いピッチ変化の連鎖は 1 音に統合 |
| ドラクエ2 序曲 | チャンネル間で発音が 1 フレームずれることがある | テンポ検出時は 1 フレーム以内のオンセットを統合 |

※ ユーザー指摘の「発音終了後に直前の音程を小さい音量で鳴らすリバーブ」は、調査した DQ2/3/4・マリオUSA では
  **同じ音程のまま音量だけを落として鳴らし続ける**方式だった（再トリガーなし・別音程なし）。

### ノートオン
1. `$4003/$4007/$400B` 書き込み（ハードウェアトリガー）。無音フレームでのトリガーは 2 フレーム以内に同じ音程で鳴り始めればトリガーフレームを開始とする
2. 音程が 0.75 半音以上離れ、2 フレーム以上続いた
3. 無音 → 発音
- 発音フレームの 6 割超でトリガーするドライバはトリガーを判定に使わない

### 余韻（ゲートオフ）判定
ノートの音量列で、次をすべて満たす最初のフレーム g を余韻の開始とする:
- g 以降の音量がすべて vol[g] 以下（再上昇しない）
- vol[g] ≤ ピーク / 2
- vol[g] ≤ max(2, ピーク / 4)（低い床）、または直前から 3 以上急落
  - ただし立ち上がりのピーク後に音量が上がり直した音（トレモロ）は、急落を余韻とみなさず低い床のみで判定
    （オホーツクに消ゆ 1ch: B,4,A,5,9,6,8,7 の減衰トレモロの後、音量 4 で持続するのが音符本体。v0.1.7 までは 7→4 で切っていた）
- 余韻が 2 フレーム以上残る

### グライド統合・最短長
- 3 フレーム以下のノートに続く、隣接した音程分割ノート（3 フレーム以下）は統合する
- 1 フレーム以下のノートは捨てる

## Phase 2 テンポ検出

1. **グリッド検出**: 2〜48 フレームの単位候補（0.2% 刻み＋整数/半整数）について、円周平均で位相を求め、許容誤差内のオンセット率を偶然一致率で補正したスコアで評価。最良スコアから 0.08 以内で最大の単位を採用。整数に十分近ければ整数にスナップ
   - ドラクエ系のテンポ累積型ドライバは 14.4 フレームのような小数単位になる
2. **2分割/3分割判定**: オンセット間隔（単位数）の過半数が 3 の倍数なら 3 分割（3連・シャッフル）
   - 2 分割: 1 拍 = 4, 2, 8, 16 行 / 3 分割: 12, 6, 3, 24 行のうち、BPM が 70〜170 に入る最初のもの
   - **シャッフル検出**: 連続する 2 つの発音間隔が (2s, s) または (s, 2s)（長短 2:1 の交互）になっている組が 45% 以上なら
     シャッフル（ストレートなグリッド上に書かれた 3 連ノリ）とみなし、1 拍 = 長短 1 組 = 3s 行（240 BPM を超える場合は 6s 行）
     - マリオ3: 単位 6 フレーム、間隔 12,6,12,6…（s = 1、86%）→ 3 行/拍・200 BPM。18 フレーム周期で見ると発音は 0 と 12 にのみ
       （24 フレーム周期では 0/6/12/18 に均等に散らばり、2 分割の解釈では構造が見えない）
     - マリオUSA: 単位 2 フレーム、間隔 12,6（s = 3、54%）→ 9 行/拍・200 BPM
     - 等間隔の連続音・付点（3:1）・8分+16分の音型は該当しない（45 本中、新たに該当したのは Kkachi-Wa Norae Chingu のみ）
     - v0.1.9 で入れた「ベースラインによる拍の補正」は、ベースが 8 分を刻む曲でテンポを 2 倍に誤判定したため v0.1.10 で廃止
3. **テンポマップ**: 8 秒窓ごとに全体グリッドの当てはまりを確認し、合わない窓は個別にグリッド検出（全体単位の 1/2.2〜2.2 倍の範囲、スコア 0.6 以上かつ全体より 0.25 以上良い場合）。同じ単位の窓を統合し、境界はオンセット単位で最適化
4. **ティック変換**: PPQ 480。最初の区間の原点は**フレーム 0 に最も近いグリッド点**（冒頭の空白を保持。ドライバは最初の PLAY から曲を開始するため）。以降の区間は区間の最初のオンセットに最も近いグリッド点。ティック = 原点からの行数 × (480 / 行数/拍)
   - 例: マリオUSA 地上は 12 フレーム目から始まる = 1 拍（18 フレーム）の 3 連 2 個分の休符 → 最初の音は 320 ティック

### 拍子・リタルダンド（v0.1.11）

- **区間の境目**: グリッドの当てはまりで決めた境目の前後で、6 行以上の空白（長い音・休符）の直後にある発音が
  ほぼ同じスコアなら、そちらを境目にする（フレーズの切れ目優先）。区間末のリタルダンドが次の区間のグリッドに
  吸われるのを防ぐ
- **テンポ追従**: 当てはまり 90% 未満の区間は、発音ごとに行を割り当てながら局所的な単位を更新する（track_rows）。
  音符の位置はグリッドに乗せたまま、テンポは **1 小節ごとの平均**で出力（DQ 系の ±1 フレームの揺れを均す）。
  本音符の直前（0.5 行未満）の装飾音は位置合わせに使わない
- **拍子**: 8 分音符 1 個より長い音の開始位置が 8 分 3 個単位（付点 4 分の拍頭）に 85% 以上、かつ 2 個単位より
  15% 以上多く揃えば 6/8、それ以外は 4/4。MIDI に拍子記号イベントを出力。`--time-sig "6/8,4/4"` で区間ごとに指定可
- **小節頭合わせ**: 2 番目以降の区間は、前の区間の最後の発音の後の小節線から始める（フェルマータ・伸ばしを吸収）。
  その間の時間は専用のテンポイベントで再現するので、演奏時間は変わらない（2 小節を超える休符は長さを保持）
- 例: DQ2 序曲 — 0〜567 フレームが 6/8（♩=137〜140、5 小節目でリタルダンド 122.7、6 小節目のフェルマータ 65.9）、
  6/8 の 6 小節ちょうど（8640 ティック）から 4/4（♩≒124〜126）。DQ1 のオープニングも 6/8 → 4/4 と判定
- 45 本で 6/8 と判定されたのは DQ1 のみ。MIDI の長さと元の演奏時間の差はおおむね ±0.2 秒以内

### 3 連系の拍の選び方（v0.1.11）
- 3 連系（シャッフル以外）は、最も多い発音間隔が 8 分音符（半拍）になる行数を優先（70〜240 BPM の範囲内のとき）
  - スーパーマリオ: 単位 3 フレーム、最多間隔 9 フレーム → 6 行/拍 = 200 BPM（3 連 = 6 フレーム = 2 行）
  - 45 本での変化: スーパーマリオ 100→200、スーパーマリオ2（Lost Levels）112.5→225、ドラキュラII 75→150

### 3 連のグリッドの拍の位置・16 分の混在・短い曲のシャッフル（v0.1.28）
- **拍の位置**: 3 連系のグリッド（3・6・9… 行/拍）では、最初の区間のどの行が拍の頭かを選ぶ。各オンセットに「次のオンセットまでの行数（1 拍まで）」の点を付け、
  3 連 8 分ずつずらした候補のうち一番高いもの（ずらさない場合の 1.15 倍以上のとき）。シャッフルでは長い方の音が拍の頭になる。
  ずらした分は曲頭の休符になる（フレーム 0 が最初の拍の途中に来る）。半拍ずらし（2 分割の問題）は扱わない
  - 例: Wrecking Crew 1 曲目 — これまではフレーム 0 の近くを拍の頭にしていて、本編のシャッフルが 3 連 1 つ分ずれていた
- **16 分の混在**: 3 連系のグリッドで、発音の始まりが 3 連の行から 1.5 フレーム以上離れ、拍の 16 分の位置から 0.5 フレーム以内なら 16 分に置く（音の終わりは対象外）
  - 例: Wrecking Crew 1 曲目の冒頭 — 16 分 2 つの前打ち（フレーム 0・6）→ 2 分 3 連 3 つ → 4 分 2 つ → 本編のシャッフル（150 BPM）。テンポは最初から同じ
    （24 フレーム/拍）で、細かさが 16 分から 3 連に変わるだけ。これまでは前打ちの 16 分が 3 連に寄せられていた
- **短い曲のシャッフル**: 長短 2:1 の判定に必要なオンセット数を 16 → 8 に（Wrecking Crew 5 曲目、2.4 秒・13 オンセット）
- **グリッド単位**: 選んだ単位が整数フレームから 2% 以内で、整数でもすべてのオンセットが同じ以上に合うなら整数にする（短い曲で 8.08 フレームなどになっていた）
  - 回帰テストの変化: Kkachi-Wa 149.90 → 150.25、Loopz 111.11 → 112.50、Karateka 74.82 → 75.00 BPM（前 2 曲は MIDI の長さが元とほぼ一致に）。他は同じ。
    nsf2mid_out の 12 曲は変更前の版と同じ出力

### ループ開始を小節頭に・区間内のリタルダンド（v0.1.29）
- **ループ開始を小節頭に**: ループが見つかった曲は、ループの開始を小節の頭とみなす。開始が拍から 1/4 拍以内なら近い拍、それ以外は直前の拍
  （ループはその拍のすぐ後の前打ちの音から始まることがあるため）。そこまでの拍数が拍子で割り切れないときは、余りの拍数（1〜3 拍）の小節を曲頭に置く
  （x/4 の拍子のときだけ。最初の区間の中にループ開始がある場合だけ）
  - 例: Wrecking Crew 1 曲目 — ループ開始 15.67 拍 → 曲頭 3/4、3 拍目から 4/4（本編が 4 小節目の 4 拍目 → 5 小節目の 1 拍目に）。
    DQ3 15 曲目 — ループ開始 2 拍目 → 曲頭 2/4。DQ2 4 曲目・マリオ 3 1 曲目は 1/4、マリオ USA 地上は 1/4
- **区間内のリタルダンド**: グリッドに合っている区間（合致 90% 以上）でも、あるチャンネルの音が普段の音より 4.5〜60% 長くなる状態が 3 音以上続き、
  その長さが少しずつ（1 音ごとに 0.2 以内）伸びていく場合はリタルダンドとみなし、その区間を音ごとに追ってテンポ変更（1 小節ごと）で再現する
  - 遅い音が切り上げで余分な行になり、小節がずれていた。一定の長さが続くだけ（付点）や、縮むだけ（Airball の曲頭の加速）は対象外
  - 例: DQ3 15 曲目 — ループ途中（28 拍目〜）と最後（60 拍目〜）の 2 か所。ループが 65.25 拍 → 64 拍ちょうど（2〜66 拍）に
- **途中で切れない区間の始まり**: 新しい区間が前の区間の最後の音から 2 行以内で始まるとき（音楽が途切れていない）は、次の小節線へ飛ばさずそのままの位置から始める。
  拍子の切り替えは次の小節線で行う（DQ3 15 曲目の最後のリタルダンドで 1/4 拍ずれていた）
- 回帰テスト: Ai Sensei・Ikari Warriors II の MIDI の長さが 0.05〜0.1 秒変化（区間の始まりの扱い）。nsf2mid_out は曲頭に短い小節が入った曲（DQ2 t04・マリオ USA t03・マリオ 3 t01）と Ai Sensei が変化

### ループ内の変拍子（v0.1.30、src/meter.py）
- 対象: ループがあり、ループの長さが 8 分音符の整数個で、4/4 の小節で割り切れない曲（最初の区間の拍子が 4/4 で、ループがその区間に収まる場合）。
  割り切れる曲は今までどおり（回帰テストの 45 本は変化なし）
- 考え方（ユーザー案「基本の 4 拍子を把握し、そこから外れた部分を探して適切な拍子を入れる」）
  - ループの始まりと終わりは小節線。変拍子の部分はループ内の 1 か所のまとまった区間とし、その前の 4/4 はループの始まりに、後ろの 4/4 はループの終わりに小節線をそろえる
  - 変拍子の区間では、L 個の 8 分音符の小節が「直前か直後の同じ長さと同じリズム」なら良い小節（6/8 の繰り返しは良く、5/8 のフィルインは繰り返さない）。
    一致度は半分なら 0、全部なら 1 に換算。4/4 以外の小節には 1 つごとに罰点（2・3 個は大きめ）
  - ドラムのフィルイン（スネアが 3 つの 8 分に続く）の直後は小節線（どの区間でも）
  - これを動的計画法で 8 分音符単位に解く。ほぼ毎 8 分で鳴るチャンネル（ベースの刻み）はリズムの情報がないので除く
  - 6 個の小節: 前半と後半が同じリズムなら 6/8、3 つの 4 分が似ていれば 3/4。偶数個は x/4（4 個 = 2/4）、奇数個は x/8（5/8・7/8）
- 確認（ユーザーが拍子を指定した曲）: Life Force（沙羅曼蛇）3 曲目 — 4/4×8、ループ 6/8 6/8 5/8 6/8 6/8 5/8、4/4×11 で一致。
  Shatterhand JP 1 曲目 — 6/8×3、4/4×2、6/8×3、4/4 で一致
- 他の候補（要確認）: Ninja Gaiden II（7/8 が 4 か所）、Silent Service（5/8 が 2 か所）、Panic Restaurant・Derby Stallion（2/4）、Mario's Time Machine（1/4）
- ループの長さが小数拍の曲（Laser Invasion 35.25 拍など）はテンポ判定の誤りが先にあるので対象外

### 長い音の周期から拍を決める（v0.1.42、ユーザー確認「3 連ノリとアウフタクトが苦手」の段階 1）
- 問題: グリッド（一番細かい行）から 1 拍の行数を選ぶ方法では、次の 2 つで 1 拍の長さを取り違えていた
  - ドライバーが 3 連符をフレームに丸めている（1 拍 20 フレームを 7・7・6、24 フレームを 9・9・6）。均等なグリッドに乗らず、細かい 2 拍子系のグリッドになる
  - グリッドは正しいが 1 拍の行数が違う（4 フレームのグリッドで 1 拍 24 フレームの曲が 32 フレーム = 8 行になる）
- 方法（tempo.note_pulse）: 各チャンネルの「長い音」（次の音まで 10 フレーム以上）の始まりと、ドラムの打点を集め、18〜51 フレームの周期で
  一番よくそろう周期（許容 1 フレーム）を求める。これは 1 拍か、その半分・2 倍
- 曲全体が 1 つのテンポで、周期のそろい方（偶然を引いた値）が 0.4 以上、かつ決めた 1 拍が周期の 1/2・1・2 倍のどれでもない（3 % 以内）ときだけ、
  周期を 2・3・4・6・8・12・16 等分したグリッドから、全部の音に一番よく合う粗いものを選び直す（今のグリッドと同程度以上に合うこと）。

### 周期の求め方の改良・6/8 のアウフタクト・3 連系の曲の変拍子（v0.1.43、段階 2・3）
- 周期（note_pulse）: 曲全体で周期がそろわないとき（0.4 未満）は、10 秒ごとの区間でそろい方を見て平均し、最後に曲全体で 0.001 フレーム刻みで詰める。
  0.1 フレーム刻みでは長い曲で誤差が積み重なっていた（Super Spike V'Ball 2 曲目: 19.82 フレーム、約 3 分。0.08 → 0.49 で 181.7 BPM の 3 連系 4/4 に）
- グリッドの選び直し（_pulse_grid）: 候補ごとに ±0.3 % の範囲で一番合う値を使う。検出済みのグリッドに近ければそのグリッド（Kkachi-Wa: 8 フレームちょうど）、
  そうでなければ整数・1/2・1/3 フレームに寄せる。当てはまりが近い候補が複数あるときは、各チャンネルの音の間隔がグリッドの倍数になっている割合で選ぶ
  （Tom & Jerry 1 曲目: 10・5 フレームの音 → 2.5 フレーム、3 連の 3.33 にしない）
- 6/8 のずれ（_detect_meter）: 長い音が 8 分 3 個の区切りに来るかを、曲頭から 8 分 1・2 個ずらした位置でも試す。
  ずらした位置で 6/8 になったら、ループ開始（なければ長い音の多い方）の付点 4 分を小節頭とし、その前をアウフタクトにする。
  アウフタクトが付点 4 分で割り切れないときは曲頭に休符を入れて 3/8 か 6/8 の小節にする（ユーザー指示「1 拍で割り切れない時は頭に空白を入れる」）。
  例: Ma Bu Mi Zhen & Qu Wei Cheng 3 曲目 = 3/8（8 分休符 2 個 + D#4）→ 6/8。長い音の 99 % が 8 分 1 個ずれた区切りに来る
- 8 分が続く 6/8（_repeats_in_six）: 長い音で区切れない曲は、旋律が 8 分 6 個後に戻る割合が 0.15 以上で、4・8 個後の 2 倍以上、かつループが 6/8 の小節で割り切れる
  （8 分の数が 6 の倍数で、8 の倍数なら 24 の倍数）ときに 6/8。同じ音が続くチャンネル（持続音）は除く。
  例: Indora no Hikari 1 曲目（0.75 対 0）、Relics 3 曲目（0.25 対 0.07）。Minna no Taabou 2 曲目は 6 個後に戻るがループ 128 個なので 4/4 のまま
- 3 連系の曲（1 拍 3 行・6 行）で、ループが 4/4 で割り切れるときは変拍子を判定しない（変拍子の判定は 8 分 = 半拍が単位で、3 連系には当てはまらない）。
  Hot Slots 2 曲目の 3/4 の誤判定がなくなった
- アウフタクト（4/4）: v0.1.42 の拍の決め方で、Minna no Taabou 1 曲目・Super Spike 2 曲目（1 拍 + 1/3 → 2/4 の前打ち小節 = 2/3 拍の休符 + アウフタクト）、
  Ai Sensei 1 曲目（1 拍 → 1/4）はユーザーの指摘どおりになった
- 適用範囲の制限（ランダム 160 タイトル × 1〜3 曲目 = 480 曲で v0.1.41 と比較して決めた）:
  - 周期による拍の選び直しは、ループのある曲で、新しい 1 拍でループが 4/4 のちょうどの小節数になるときだけ。

### エコー・分散和音の 6/8・長いループ（v0.1.44、meter_check.md のユーザー回答 2026-11-05）

### 速い音符群（アルペジオ）は先頭だけを発音タイミングに（morokoshi v2.9.26、ユーザー案）

チップチューンでは、2〜3 音を 1〜3 フレームずつ交互に鳴らして和音に聞かせる（アルペジオ）。
ユーザーの決定: **MIDI には元の音のまま細かく出す。テンポ・拍子の判定には使わない**（群の最初の音だけを使う）。

- `nsf2mid.fold_fast_figures`: 判定用の音符（エコーを除いた後）で、開始の間隔が `FAST_GAP`（3 フレーム）以下の音が
  2 音または 3 音を繰り返している並び（`n` 番目の音 = `n-2` 番目、または `n-3` 番目）を `FAST_MIN`（4 音）以上見つけたら、
  最初の音から最後の音の終わりまでの 1 つの音にする。和音が替わると繰り返しが崩れるので、そこから次の群になる

    共通の音がある所（D4/A3 → E4/A3）も区切れる
- `fine_rows`: テンポはまとめた音で決まるが、MIDI には元の音が残る。まとめて外した音（群の 2 音目以降）の 85 % 以上が
  グリッドの 1/2・1/4 に乗る区間は、1 拍の行数を 2・4 倍にする（BPM は同じ）。位相は 480 フレームごとに取り直す

- SPC には使わない。ループ検出も従来どおり（全部の音で判定）
- 結果: バルーンファイト 1 曲目は 150 BPM の 1 区間に（従来は区間 4 つ・途中にテンポ追従）。レッキングクルー 2 曲目は 150 BPM のまま
  （3 フレーム × 8 行）。ランダム 150 本のうち、まとめる処理が働いたのは 6 本・結果が変わったのは 4 本
  （上記 2 曲のほか Treasure Master: 後半のテンポ追従がなくなった、Ganbare Pennant Race!: 1 拍の行数 8 → 16）。
  回帰テスト 45 本・変拍子の正解曲は変化なし

**未対応: 上昇下降型（シルバーサーファー）** — 1〜2 フレームごとに音程が同じ向きに動き続け、また戻って繰り返す

### アルペジオの和音・4 音・グライドとの区別（morokoshi v2.9.27）

- 判定は `notes.arpeggio_end` に一本化（`nsf2mid._arpeggio_end` は FAST_GAP / FAST_MIN で呼ぶだけ）。条件:
  - 2・3・4 音を、開始の間隔 3 フレーム以下で繰り返す。**3・4 音は 2 周以上**（速い音階をアルペジオにしない）
  - **すき間なく続く**（前の音が終わる所で次が始まる）。Mega Man 2 の三角波は A#4 D#4 A3 G3 のキックを 8 フレームごとに無音をはさんで鳴らす
  - **12 フレーム以上**（`ARP_MIN_FRAMES`）。Ganbare Pennant Race! の 1ch は G2/E2 を 9 フレームだけ、1 拍ごとに鳴らす（ドラム）
  - **ドラムの連打は除外**（`_drum_roll`）: 周期に 1 回、同じ音で鳴らし直し、そこから下がり続ける（Kart Fighter の三角波 F5 C#5 A#4 を 6 フレームごと）
- **グライドとしてまとめない**（`notes.merge_slides`）: アルペジオの音（`cue` に `+arp`）は前の短い音にくっつけない。
  M.C. Kids 2 曲目 2ch の G4 B4 D5（2 フレームずつ、D5 は鳴らし直さない）で D5 が B4 にくっついて消えていた。
  アルペジオの音は下降音ドラムにもしない（`drums.split_drop_drums`。Stunt Kids 2ch の D5 A5 F#5）
- **`--arp-chords`**（morokoshi の MIDI オプション「アルペジオを和音にする」、既定オフ）: `nsf2mid.arpeggio_chords` がアルペジオを
  使っている音の和音にする（群の頭から、最後の音の終わりまで）。テンポ・拍子の判定は変わらない。SPC には使わない
  - レッキングクルー 2 曲目 2ch: 1 拍ごとに E4+G#4 → C#4+E4 → D4+F#4 …、M.C. Kids 2 曲目 2ch: G4+B4+D5

### 複数の拡張音源が指定された NSF（morokoshi v2.9.27）

### リタルダンドの跳び・前打ちの取り消し・3 連の拍の頭・リズム隊の拍（morokoshi v2.9.28、meter_check.md のユーザー回答 2026-11-07）

- **リタルダンドの判定**（tempo.has_ritardando）: 1 音ごとの長さの変化は普段の音の 0.2 倍まで、**または 2 フレームまで**（RIT_STEP_FRAMES）。
  短い音では両端がフレームに丸められるので 2 フレーム跳ぶことがある
  - FF3 2 曲目（FF2 1 曲目と同じ曲）: 16 分が 9・10 フレームの交互（平均 9.48）、16 小節目で 13 フレームまで遅くなり（11, 13, 12, 13）、1 小節目で戻る。
    13 → 11 の跳びで判定から外れ、固定のグリッドで 256 音が 259 行 → 4/4 で割り切れず 6/8 になっていた。
    今は追従して 4/4、16 音 = 1 小節（ユーザー「16 音ごとに上昇と下降」）。FF2 は 9 フレーム一定なので元から問題なし
- **エコーの遅れの幅**（nsf2mid.drop_echoes）: 見つけた遅れ d に対し ±max(1, 0.5 d) フレームまでをエコーとして除く（ECHO_SLACK）。
  遅れはドライバーのティック数なので、リタルダンドの中ではフレームで伸びる（FF3 2 曲目: 13 → 15〜18 フレーム。残ったエコーで小節線がずれていた）
- **前打ちの取り消し**（nsf2mid.check_pickup、ユーザー「スネアは 2・4 拍に入ることが多い」「アウフタクトはベースやドラムが入らないか違う挙動」）:
  ループ開始を小節頭にするための前打ち（奇数拍）は、次の両方のとき入れない
  - ノイズが 16 回以上鳴り、8 割以上が拍の頭で、その 8 割以上が 1 拍おき。前打ちがあると 1・3 拍、なければ 2・4 拍になる
  - 三角波が前打ちのすべての拍で鳴っている
  - Platoon 1 曲目（ループ開始 0.6 秒 = 1 拍目の後 → 1/4 の前打ちだった）、Spelunker 2 曲目
- **3 連のグリッドの拍の頭**（tempo.beat_phase）: 「次の音までの長さ」をチャンネルごとに測る。全チャンネルをまとめると、
  別のチャンネルが同じ音型を少し遅れて鳴らす曲で音が短く見える（Bikkuriman World 2 曲目: P2 = P1 の 15 フレーム後で拍の頭が 8 分の途中になり、
  休符 + 前打ちが入っていた → 6/8、前打ちなし、ベースの入りが小節頭）。Balloon Fight 3 曲目も前打ちがなくなった。Wrecking Crew 1 曲目は変わらない
- **リズム隊の拍**（tempo._detect_tempo_map、ユーザー「ch3 かリズムを基準にすれば判定できる」）: ループのない曲でも、三角波 + ドラムだけの周期（note_pulse）が
  0.6 以上そろい（RHYTHM_NORM）、全チャンネルの周期と 1 % 以内で一致すれば、その周期を拍にする（2 分割でも 240 BPM まで）。テンポ追従はしない

### ループのない曲の小節頭・3 連系の拍の決め方（v0.1.33）
- **ループのない曲の小節頭**: ループ開始が使えないので、拍ごとに「拍の頭で始まる音の長さ（最大 4 拍）」を合計し（ベース = 一番低いチャンネルは 2 倍）、
  小節の何拍目が一番重いかを見る。1 拍目（曲の頭からの数え方）より 1.25 倍以上重い拍があれば、そこを小節の頭として曲頭に前打ちの小節を置く（拍の頭の音 16 個以上のとき）

    - 30 秒未満の曲は判定しない（ユーザー判断「短い曲は無理に解析しなくて良い」）

### 1 小節ごとに繰り返す区間のテンポ（v0.1.35、ユーザー案「1 小節単位でフレーズがほぼ同じなので抽出できる」）
- 2 番目以降の区間で、発音の 85% 以上が一定の間隔（グリッド単位の 4 の倍数）の後にもう一度来るなら、その最短の間隔を 1 小節（4/4）とみなしてテンポを決める
  （1 小節に 1 回か 2 回か: 前の区間のテンポに近い方）。これまでは前の区間に近いテンポを選ぶだけだった
- 区間の始まり: 音型が繰り返し始める最初の音（1 小節前まで遡る）。区間の終わり: 音型を 1 小節ずつ追い（70% 以上一致）、最後の繰り返しの次の小節が区間の最後の小節
- グリッド単位は小節の実測（最初から最後の繰り返しまで）で決め直す（窓での推定は 7 小節で半行ずれた）
- 最後の小節の中で次の区間のテンポに切り替わる位置: それ以降の音がすべて次の区間のグリッド（次の小節頭から逆算）に乗り、それより前の音が今の区間のグリッドに乗る最初の音。
  そこからは小節線に飛ばさず、小節の途中から次の区間を始める
- 例: DQ3 26 曲目 — 57 小節目（フレーム 8100）から 135 BPM の音型が 7 小節、64 小節目は 3 拍で音型が遅くなり、4 拍目からイントロの 100 BPM で「ソ・ド・レ」の 3 連、
  65 小節目の頭で長いソ（イントロと同じフレーズ）。これまでは 89.9 BPM（1 小節が 2.67 拍）、区間の始まり・終わりもずれていた
- 回帰テスト・確認済みの曲（変拍子 3 曲、Wrecking Crew、DQ3 15 曲目）は変化なし

### 3 連ノリの検出（v0.1.15）
- シャッフル（合算したオンセットで長短 2:1）でも 3 分割でもない曲について、**チャンネルごとに**見る
  （2:1 のベースと 3 連のメロディーを合算すると等間隔のグリッドになり、ノリが消えるため）
  - チャンネルごとの最多発音間隔 d（4 フレーム以上）を 3 連の 8 分とみなし、周期 3d（1 拍 = 3 音）と 4d（1 拍 = 4 音）を比較
  - 「1〜2 周期後に同じ音程が鳴る率」が 3d の方が 0.15 以上高く、かつ「周期に対する拍のそろい（beat_fit）」が 0.05 以上良ければ 3 連ノリ

- `--triplets on` は判定を省略して 3d を 1 拍にする（チャンネルが足りなければ 3 分割の行数候補）。`off` はシャッフル・3 分割も使わない

## Phase 3 ドラム

ノイズ・DPCM は GM パーカッションのノート番号に割り当て、ノイズ → MIDI ch 4、DPCM → ch 5 に出力する（v0.1.23〜。v0.1.22 までは ch 10）（下降音ドラムは下記）。コンソールに「種類 → GM ノート」の一覧を出すので、
違和感があれば `--drum-map` で上書きする。

### ノイズ
- ヒット開始: `$400F` 書き込み（発音中）、無音 → 発音、音量が 3 以上跳ね上がる（音量だけで叩き直すドライバ）
- 1 ヒット中に周期を変えるドライバが多い（ロックマン2 のスネア: 11→0→5→10→15）ため、
  **音量で重み付けした平均周期番号**・ヒット長・モードで分類する
- ヒット長は余韻判定（Phase 2 と同じ）で測る（DQ2 はノイズも音量 1 の余韻を保持する）

| 平均周期番号 | 長さ | GM |
|:---|:---|:---|
| ≤ 4.5（明るい） | ≤ 5 フレーム / ≤ 12 / それ以上 | 42 Closed HH / 46 Open HH / 49 Crash |
| 4.5〜9.5 | ≤ 20 / それ以上 | 38 Snare / 49 Crash |
| ≥ 9.5（暗い） | ≤ 8 / それ以上 | 36 Kick / 41 Low Floor Tom |

### DPCM
- サンプル開始ごとに 1 ヒット。エミュレーション中にサンプルのバイト列を取得し、1bit デルタを復号
- 40Hz ハイパス後のゼロ交差数から明るさ（おおよその周波数）を推定して分類

| 推定周波数 | 長さ | GM |
|:---|:---|:---|
| < 1200 Hz | < 120 ms / それ以上 | 36 Kick / 45 Low Tom |
| < 4500 Hz | — | 38 Snare |
| それ以上 | < 80 ms / それ以上 | 42 Closed HH / 46 Open HH |

- ループ再生のサンプルは音程楽器とみなしてスキップ
- **音程付きサンプル（v0.1.23〜）**: 同じサンプル（アドレス・長さ）を複数のレートで鳴らしている場合、ドラムではなく音程のある音色とみなし、
  サンプルごとのトラック `Ch5 DPCM $ADDR`（同じアドレスで長さ違いがあれば ` len N` を付ける）に分ける。ch 5
  - 音程は波形から推定する（v0.1.24〜）: 復号したサンプルの自己相関から 1 周期のビット数 P を求め、周波数 = CPU / 周期表[レート] / P
    - 自己相関の山のうち、最大の 90% 以上ある最初の山を採用（倍の周期を拾いにくくする）。最大の山が 0.5 未満なら「周期なし」
    - 先頭 1024 バイト（8192 ビット）で計算。numpy が無い環境では周期なし扱い
    - 周期なし（複数レートで鳴らすドラムなど）: レート間の音程のまま、一番低いレートを 48（C3）にする
    - 確認: Journey to Silius のベース素材 5 種が 288 / 272 / 256 / 240 / 226 ビット（A#・B・C・C#・D、半音ずつずらした素材）、
      暴れん坊天狗 $C180 = 288 ビット・$C980 = 381 ビット。ベースは E1〜C3 付近に出る。オクターブは 1 つずれる可能性がある
    - v0.1.23 はレートだけで決めていた（32 ビット = 1 周期とみなす。レート 0 = C3 〜 15 = C6）
  - `--drum-map` で割り当てたキーはドラム扱いのまま
  - 確認: Journey to Silius（DPCM ベース、$C400 が F4〜C6 の 5 音）、Gimmick!、スーパーマリオ3 #1（$D800 を 2 レート）
- DMC は 1 音ずつしか鳴らないので、次のサンプル開始で前の音を切る（v0.1.23〜）
- 確認: スーパーマリオ3 の 4 サンプルが Kick / Snare / HH / Tom に分かれた

### 下降音ドラム（三角波キック・矩形波タム）

## Phase 5 拡張音源（v0.1.25〜）

計画は docs/expansion_plan.md。MIDI ch は morokoshi のチャンネルボタンの番号と同じ（2A03 = 1〜5、拡張音源 = 6〜。
複数の拡張音源を同時に使う NSF は考えない。ch 10 が GM のドラム ch であることは気にしない＝GM 音源での再現は目的外）。

### FDS（v0.1.25）
- 対象: ヘッダーの拡張音源バイトに FDS（$04）が立っている NSF。トラック `Ch6 FDS`、MIDI ch 6
- **メモリ**（nsf.py）: $6000〜$FFFF をすべて書き込み可能な RAM にする。バンク切替なしはロードアドレス（$6000 以上）に置く。
  バンク切替ありは $5FF6〜$5FFF で 4KB ずつファイルからコピー（$5FF6/$5FF7 = $6000/$7000、初期値は $E000/$F000 と同じ $76/$77）。
  v0.1.24 まではロード $8000 未満がエラー（Dead Zone・Deep Dungeon II など）
- 起動時に $4089 = $00・$408A = $E8・$4080 = $80 を書く（BIOS が残す状態）。$4040〜$408A の書き込みを記録、$4040〜$407F・$4090・$4092 の読み出しに応答
- **音源モデル**（apu_state.FDS）: 周波数 = CPU × F ÷ (65536 × 64)、音量エンベロープ（$4080 直接 / 自動、周期 8 × (速度 + 1) × $408A クロック）、
  音量 = ゲイン（0〜32）を 0〜15 に換算（ゲインが 1 以上なら 1 以上）。波形停止（$4083 bit7）・波形書き込み中（$4089 bit7）・周波数 0 は無音。
  マスター音量（$4089）は音量に掛けない
  - **波形の周期数**: 波形メモリ 64 サンプルが完全に繰り返している（32 / 16 … サンプルごとに同じ）なら、その回数ぶん高い音
    （バイオミラクルぼくってウパは 2・4 周期の波形 → 1・2 オクターブ上）
  - モジュレーション（$4084〜$4088）は記録のみ。音程は中心の周波数で判定し、MIDI には出さない（ユーザー判断）
- 音符の判定は矩形波と同じ（$4083 の書き込みを発音の合図の候補、波形の切り替えは音色の変化として扱い新しい音符にしない）。下降音ドラムの対象にはしない（ユーザー判断）
- テンポ・拍子・ループ検出の入力に FDS の音符も入れる
- `--dump`: writes.csv にレジスタ名、frames.csv に FDS 列、tracker.txt に FDS セル（音名・音量・波形番号）
- **確認**（libgme で FDS だけを鳴らし、音程と発音を比較）:
  - 音程の一致: ゼルダの伝説 157/167 フレーム、光神話 178/194、帰ってきたマリオブラザーズ 90/99、バイオミラクル 1 曲目 145/215（残りは ±1〜3 半音の揺れ）
  - 発音・無音の不一致は libgme の余韻（音量 0 の後も 1〜2 フレーム鳴る）によるもので、レジスタの書き込みどおり
  - FDS の 122 本すべて 1 曲目を変換してエラーなし。FDS の音符 0 の曲は libgme でも FDS が鳴っていない（1 曲目で FDS を使わない・FDS 音源を使わないゲーム）
- **未解決**: 1 周期の中に減衰するパルスを 4 つ並べたような波形（バイオミラクル 3 曲目、愛戦士ニコル 1 曲目の一部）は、
  libgme の推定では 1〜2 オクターブ上に聞こえる。完全な繰り返しではないので周期数の補正をしていない。耳での確認待ち

### 共通の仕組み（v0.1.26）
- `expansion.py` に音源ごとのクラス（FDS / VRC6 / VRC7 / MMC5 / N163 / Sunsoft5B）。共通の形: CHANNELS（チャンネル名と表示名）・
  handles（担当アドレス）・write（再発音したチャンネルを返す）・read・advance・snapshot（音程・音量 0〜15・音色番号）
- MIDI ch とトラック名は `channel_table()`: libgme のボイス順（= morokoshi のチャンネルボタン）で ch 6 から番号を振る。トラック名は `Ch{番号} {表示名}`
- 再発音の合図: 音源ごとの「キーオン / 周波数の上位レジスタ」の書き込みを、2A03 の $4003 と同じ扱い（written の reg 3）にする
- 複数の拡張音源を持つ NSF: すべて動かし、ch 6 から続けて番号を振る（16 を超えたら 16）。警告を出す。
  テスト用 NSF で $07（VRC6+VRC7+FDS）・$03 の 9 本はヘッダーの誤りと思われ、どれも拡張音源の音符は 0

| 音源 | チャンネル（MIDI ch） | 音程 | 音量 | 再発音の合図 |
|:--|:--|:--|:--|:--|
| VRC6 | Saw（6）・Pulse 1（7）・Pulse 2（8）| 矩形波 CPU ÷ (16 × (P+1))、ノコギリ波 CPU ÷ (14 × (P+1))。$9003 の 16 倍・256 倍も反映 | 矩形波: 音量 0〜15（bit7 の DAC モードは無音扱い）、ノコギリ波: 増分 0〜42 を換算 | $9002 / $A002 / $B002 の書き込み（有効ビットあり）|
| VRC7 | FM 1〜6（6〜11）| fnum × (3.579545MHz ÷ 72) × 2^block ÷ 2^19 × 倍率。倍率 = モジュレータとキャリアの MULT の最大公約数（内蔵音色はすべて 1）| キーオン中 15 − 減衰量 | キーオン（$20〜$25 の bit4 が 0 → 1）|
| MMC5 | Pulse 1（6）・Pulse 2（7）| 2A03 の矩形波と同じ（スイープ・低周期の消音なし）。エンベロープ・長さカウンタは 240Hz | 2A03 と同じ | $5003 / $5007 |
| N163 | Wave 1〜8（6〜13）| CPU × F ÷ (15 × 65536 × 使用ch数 × 波形長)。波形長 = 256 − ($x4 & $FC)（6 ビット）| 0〜15 | $x4（周波数上位・波形長）の書き込み |
| 5B | Tone A〜C（6〜8）| CPU ÷ (32 × 周期) | 0〜15（エンベロープ指定は 15）。ミキサーでトーンが無効なら無音 | 周期の上位レジスタ（1 / 3 / 5）|

- N163: チャンネル i（Wave i+1）のレジスタは $40 + 8i。使用 ch 数 n のとき鳴るのは Wave 9−n〜8（1 ch だけの曲は Wave 8 = ch 13）。
  $4800 の読み出しで自動インクリメントするアドレスは、再生用の書き込みログに $F800 への書き込みとして記録する（再生側とずれないように）
- MMC5: ExRAM（$5C00〜$5FF5）と乗算器（$5205 / $5206）もバスで扱う。PCM（$5010 / $5011）は無視
- 5B: ノイズとハードウェアエンベロープの形は扱わない
- 波形の周期数（FDS・N163 共通）: 波形が完全に繰り返していれば、その回数ぶん高い音

## Phase 6 GBS（v0.1.27）

ゲームボーイの GBS を NSF と同じ流れで MIDI にする。再生エンジン（morokoshi の libgme）と同じ動きになるよう、メモリ配置・起動手順は libgme の Gbs_Emu に合わせた。

- **チャンネル**: Square 1 = P1（ch 1）、Square 2 = P2（ch 2）、Wave = TRI（ch 3、トラック名 `Ch3 Wave`）、Noise = NOI（ch 4、GM ドラム）。
  morokoshi のチャンネルボタン 1〜4 と同じ番号。DPCM（ch 5）はない
- **CPU**（cpu_sm83.py）: SM83 の全命令（CB 付きを含む）。サイクルは T ステート（4.194304 MHz）。割り込みはなし（INIT / PLAY を直接呼ぶ）。
  HALT・STOP はその呼び出しの終わりとみなす。RST n はロードアドレス + n へ飛ぶ（GBS の仕様）。未定義命令で停止
- **メモリ**（gbs.py）: $0000〜$3FFF = バンク 0（ファイルのデータをロードアドレスに置く）、$4000〜$7FFF = 切替バンク（$2000〜$3FFF への書き込み。
  ROM が 1 バンクを超えるときバンク 0 の選択は無視）、$A000〜$FFFF = RAM（$E000〜$FF7F の初期値は $FF）。
  起動時の APU レジスタは libgme と同じ値。DIV・STAT・LY は CPU のサイクルから作る（Wedding Peach は INIT で HBlank を待つ）
- **PLAY の間隔**: ヘッダーの TAC bit 2 が立っていればタイマー（(256 − TMA) << シフト）、なければ VBlank（70224 サイクル = 59.73 Hz）。
  INIT が TMA/TAC を書き換えた場合はその値を使う。曲の途中で変わった場合は警告を出し、最初の間隔のまま
  - 150 Hz を超える PLAY（Hudson の 1618 Hz など）は、約 60 Hz になるよう複数回の PLAY を 1 フレームにまとめる（ノート・ドラム判定は 60 Hz 前提のため）
- **APU モデル**（gb_apu.py）: 長さカウンタ（256 Hz）・スイープ（128 Hz）・エンベロープ（64 Hz）・DAC・NR51 のパン（左右どちらにも出ていない ch は無音）・NR52 の電源
  - 矩形波: 周波数 = 131072 ÷ (2048 − x)。Wave: 65536 ÷ (2048 − x) × 波形の繰り返し数（32 サンプルに 2 周期あれば 1 オクターブ上）。平らな波形・音量 0% は無音
  - 音量変更のための再トリガー: GB のドライバーは発音中の音量を変えるとき NRx2 を書いてトリガーし直す（エンベロープはトリガーでしか読み直されない）。
    同じ半音（ノイズは同じ NR43）で発音中に、今の音量より小さい音量で再トリガーした場合は同じ音の続きとする。同じか大きい音量なら新しい音（連打）
  - ノイズの周波数（524288 ÷ r ÷ 2^(s+1)）は一番近い NES ノイズの周期番号に換算し、NES と同じドラム分類を使う。7 ビットモード = mode 1
- **確認**（libgme で 1 ch ずつ鳴らして音程と発音の有無を比較）: カービィ・ゼルダ夢をみる島・テトリス・ポケモン赤・ロックマンワールド・ドンキーコングランド・
  悪魔城すぺしゃる（Castlevania Adventure）・スーパーマリオランド などで音程はほぼ一致（ずれは 3000 Hz 超の短い音など推定側の誤り）
  - libgme は曲頭の無音を飛ばすので、比較では時間がずれる（Metroid II は 40 フレームの待ちあり）。MIDI は曲頭の無音を保持する（NSF と同じ）
  - ランダム 60 本を 90 秒ずつ変換してエラーなし。NSF の回帰テストは完全一致
- GUI: `.gbs` / GBS 入りの zip を開ける。m3u は `file.gbs::GBS,番号,曲名 - 作曲者 - ゲーム - ©,...`（番号は 0 始まり → +1 して表示）。曲名は後ろの 3 項目を除いたもの

## Phase 3 ループ・曲終端

- 60 秒ずつエミュレートし、毎回ループ検出を行う
- **チャンネルごと**にイベント列（開始フレーム, 音程 or ドラム種類）を末尾から比較し、
  一定周期 L で一致し続けるラグを探す（DQ 系の累積テンポで生じる ±2 フレームのずれは許容）
  - 一致が最も前（ループ点に近い）まで続くラグを採用（曲中の「A A B」のような短い繰り返しは途中で途切れるので除外される）
  - 全チャンネル共通の周期 = 各チャンネル周期の最大値。ループ開始 = 全チャンネルが繰り返し始める最も遅い点
- **確定条件**: ループ本体が **3 回連続**で一致（2 回繰り返した後にサビが入る曲があるため）、
  かつ連続する 2 回の検出で同じループ、かつ 1 周目の後に 20 秒以上の繰り返し（短いループ用）
  - 2 回一致で確定していた v0.1.2 では Hydlide 3 が「2 回繰り返し→別展開」を誤ってループと判定していた
  - ループ確定には「イントロ + ループ長 × 3」のエミュレーションが必要（`-s` 既定 600 秒）
- 最後の音から 4 秒無音なら「曲終了」（ジングル等）
- 出力範囲: イントロ＋ループ × `--loops`。Track0 に `loopStart` / `loopEnd` マーカー、Pulse1 に CC111（RPG ツクール形式）

### 三角波の線形カウンタ競合（DQ2 街で発見）
`$400B` 書き込みと `$4008` 書き込みの間に APU のクォーターフレームが入ると、線形カウンタが古い値（0）で
再ロードされ、その音が鳴らない。実機でも起こり得る（ドライバのタイミング問題）が、MIDI としては意図された音を
出すべきなので、`$400B` 直後（4000 サイクル以内）の `$4008` 書き込みでは再ロードを適用する。
これでループ 1 周目だけ三角波の音が欠けてループ点がずれていた問題が解消した。

### 既知の課題（今後）
- テンポの倍/半分の曖昧さ（例: スーパーマリオ 100 ⇔ 200 BPM）。`--tempo half/double`（GUI の「テンポ」）で手動補正可
- 小節頭（ダウンビート）の検出はループ開始を使うだけ（v0.1.29）。ループがない曲は曲の開始（フレーム 0）を 1 拍目とみなす
- ピッチベンド出力（ビブラート・スライド）は未実装
- 3 連と 2 分割が頻繁に切り替わる曲（Ai Sensei 等）はテンポマップが細切れになる
- ループ点は小節頭にスナップしていない
- ドラム分類は経験則。曲ごとに `--drum-map` での調整が必要な場合がある
